# PR Review Agent — Deployment (Docker + Alembic) Plan (Plan 7 of N)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the agent deployable anywhere Docker runs: a container image, a `docker-compose.yml` (SQLite volume by default, an opt-in Postgres profile for horizontal scaling), and Alembic schema migrations run on startup — so a fresh or upgraded deploy manages its own database schema.

**Architecture:** Alembic owns the production schema (an initial migration mirrors the current models); a small `run_migrations(url)` helper applies migrations programmatically, and `main.run()` calls it before serving. `init_db` (create_all) stays for the offline test suite. The image runs `python -m app.main`; compose mounts a volume for the SQLite file and exposes port 8000 with a `/health` healthcheck. Switching `store.url` to Postgres (via the compose profile) needs no code change — SQLAlchemy is already generic and the only SQLite-specific engine option is guarded.

**Tech Stack:** Python 3.11+, Alembic, Docker, docker-compose. Existing: FastAPI, SQLAlchemy, httpx.

## Global Constraints

- Python 3.11+ (`from __future__ import annotations`).
- **No network / no Docker daemon in tests.** Alembic migrations are tested against a temp-file SQLite; compose/Dockerfile are validated by parsing/among-contents assertions, not by building images.
- Alembic is the production schema source of truth; `init_db` remains only for the test suite and is idempotent (`create_all` skips existing tables).
- The initial migration must reproduce the current schema exactly: tables `jobs`, `posted_comments`, `dead_letter`, with the `uq_job` unique constraint on `(platform, repo, pr_number, head_sha, task)`.
- Postgres support requires NO code change beyond what exists; a test asserts `make_engine` applies the SQLite busy-timeout only for SQLite URLs and not for Postgres URLs.
- The container entrypoint runs migrations then the app; `main.run()` stays `# pragma: no cover` (blocking), with `run_migrations` and `build_app` as the tested seams.
- Every code change lands via TDD: failing test first, minimal impl, green, commit.

```python
from __future__ import annotations

from alembic import context
from sqlalchemy import engine_from_config, pool

from app.store.tables import Base

config = context.config
target_metadata = Base.metadata


def run_migrations_offline() -> None:
    url = config.get_main_option("sqlalchemy.url")
    context.configure(url=url, target_metadata=target_metadata, literal_binds=True)
    with context.begin_transaction():
        context.run_migrations()


def run_migrations_online() -> None:
    connectable = engine_from_config(
        config.get_section(config.config_ini_section, {}),
        prefix="sqlalchemy.",
        poolclass=pool.NullPool,
    )
    with connectable.connect() as connection:
        context.configure(connection=connection, target_metadata=target_metadata)
        with context.begin_transaction():
            context.run_migrations()


if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()
```

```python
from __future__ import annotations

import os

from alembic import command
from alembic.config import Config

_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))


def run_migrations(url: str) -> None:
    cfg = Config()
    cfg.set_main_option("script_location", os.path.join(_ROOT, "alembic"))
    cfg.set_main_option("sqlalchemy.url", url)
    command.upgrade(cfg, "head")
```
